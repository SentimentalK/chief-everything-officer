# Personal Data Rule

`personal/` 保存可跨任务复用的用户背景、经历、关系、资产、偏好与长期判断。公开常识不属于这里；用户与外部事物之间的经历、选择和关系可以属于这里。孤立 episode 优先放 Journal；重复性日常 observation 优先放 Well-being；当前事项的执行状态放 Task。

## 文件与发现

每个文件围绕一个清晰主题，使用能说明内容的文件名，顶部提供简短说明：

```markdown
# [标题]

- Purpose: 为什么有这个文件。
- Read when: 什么情况下需要读取。
- Contains: 包含哪些内容。
```

按文件名和顶部说明发现相关背景，不另建全局 personal 索引。正文按主题组织，不要求所有个人数据使用同一 schema。

## 写入与维护

不论信息来自哪个任务或讨论，只要已确认具有跨事项复用价值，就在当次记录中维护到这里，不等原任务结束。先查找已有主题文件；更新已有信息，避免另建平行事实来源。相关 Task 或 Resource 需要这些背景时保留具体引用，不复制维护正文。

可复用不等于永久不变：偏好可以有适用条件、期限和变化。仅针对当前任务的选择或要求留在 Task，围绕单个材料的初步判断留在 interactions；不把它们未经确认地升级成长期状态。写入时分清事实、主观体验和待验证推断，单次行为不足以确定人格或因果关系。

允许信息不完整。当前确实需要、用户容易回答的缺口可以简短追问；其余先保留已知内容。某个缺口反复妨碍实际任务时，提醒用户补充；资料难以当场取得时可建议建立补录任务，不无限忽略，也不为所有空字段创建任务。

状态变化时更新当前事实，并保留有解释价值的旧状态、变化时间及原因；不让旧历史继续冒充现状。条件性偏好记录适用条件，不把某时某地的选择写成永久倾向。

一次 observation 是否进入 Personal，取决于它是否已经形成跨场景可复用的当前状态、偏好、约束或长期结论。原始睡眠、精力、饮食、routine adherence、训练和其他重复性观察由 Well-being 保存；不要因连续出现几次就直接抽象成人格、偏好或因果关系。只值得记住“发生过”的 episode 按 Journal 规则记录；稳定结论、值得保留的事件背景和 Well-being observation 可以在同一轮分别更新各自 owner。出现明确的后续行动或等待时，按 Task 规则创建或更新对应事项，不把行动进度长期维护在 Personal。没有长期状态、事件或行动需要就不额外建记录。
