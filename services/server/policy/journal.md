# Journal Rule

`journal/` 保存用户生活随时间发生或表达的具体片段，使未来的理解不只依赖当前对话或已经归纳好的个人资料。记录不以事情大小、结论成熟度或当下可见的用途为门槛；日常经历、感受、关注、意图及变化，都可能在以后产生联系。

## 文件组织

Journal 按自然季度分片：

```text
journal/YYYY-QN.md
```

例如：

```text
journal/2026-Q3.md
journal/2026-Q4.md
```

写入时根据事件发生时间选择对应季度文件；文件存在则 append，不存在则 create。季度文件只是物理分片，不改变 Journal 的语义。跨季度检索先按日期、关键词或相关季度定位，不默认读取全部历史。

## 什么时候记录

用户在自然对话中透露自身生活时，就可以进入记录流程，不必依附 Task，也不要求再次明确说“记一下”。在工作区记录约定下保存简短条目，尊重用户不记录的要求；不为记录打断交流，也不要求用户提供完整经过。

记录正面、负面和中性的片段，不只保留困扰或重大成果。对话中的假设、示例、引用和对产品的讨论不是用户实际经历；用户叙述的主观体验按其表达记录，不当作外部事实或心理结论。

系统日志、普通代码修改、实施方案和执行清单留在项目或工具中。项目相关内容只有在体现用户的实际行动、体验、意图或变化时才进入 Journal，不复制 Task 历史或整段聊天。

## 记录什么

用少量文字保留实际知道的时间、发生或表达的内容、必要情境及用户当时的体验。简化措辞，不抹掉区分情境的线索；没有的信息不补猜，不要求每条记录字段齐全。

区分意图、尝试、行动、结果与评价；未记录行动不等于没有行动。发生时间不确定时注明，不把记录时间冒充发生时间。AI 的解释如确需保存，标明推断或待验证理解，不把情绪、梦境或单次行为解释成人格和因果结论。

区分同一事件的再次讲述与新的发生。补充旧事件时关联原记录，确有新的发生或表达时保留新的时间；不把重复叙述计成多次发生，也不将类似事件合并到看不出其先后。提及频率只是部分观察，不等于实际发生频率。

## 维护与分流

默认追加记录。更正用 follow-up 指明修正哪次旧事件，不把后来知道的内容伪装成当时已知；用户明确要求纠正、删除或整理时按其要求处理。归纳或精简不应无声抹去事件时间、区别和不确定性。

写 Journal 时，已确认的可复用个人状态当次按 Personal 规则更新；明确的行动、等待或监控按 Task 规则跟进；经过实际权衡且未来值得作为 precedent 的具体选择按 Decision 规则记录。Journal 保留发生或表达的片段，Personal 维护当前长期状态，Decision 维护选择及其当时条件，Task 维护下一步，不复制维护细节和进度。同一事件出现在多个领域仍是同一份证据，各处只保存自己的语义。

当前先保证记录忠实、简洁、可追溯，不为每条片段预先寻找历史关联、生成聚类或读取全部季度 Journal。主动检索与跨事件归纳按需要 progressive retrieval，不是保存的前置步骤。
