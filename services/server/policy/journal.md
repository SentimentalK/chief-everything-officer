# Journal Rule

`journal/` 保存用户生活中值得以后记住的具体 episode、经历、感受、关注、意图及变化，使未来的理解不只依赖当前对话或已经归纳好的个人资料。Journal 不是 daily telemetry：重复性身心状态、routine behavior 和主要依赖纵向比较才有价值的 observation，优先由 Well-being 保存。

## 文件组织

Journal 按自然季度分片：

```text
journal/YYYY-QN.md
```

例如：

```text
journal/2026-Q3.md
journal/2026-Q4.md
```

写入时根据事件发生时间选择对应季度文件；文件存在则 append，不存在则 create。季度文件只是物理分片，不改变 Journal 的语义。跨季度检索先按日期、关键词或相关季度定位，不默认读取全部历史。

## 什么时候记录

用户在自然对话中透露自身生活时，可以直接进入持久化判断，不必依附 Task，也不要求再次明确说“记一下”。但先判断它是值得保留的 episode，还是主要用于纵向比较的 routine observation：前者进入 Journal，后者进入 Well-being。尊重用户不记录的要求；不为记录打断交流，也不要求用户提供完整经过。

记录正面、负面和中性的片段，不只保留困扰或重大成果。对话中的假设、示例、引用和对产品的讨论不是用户实际经历；用户叙述的主观体验按其表达记录，不当作外部事实或心理结论。

普通睡眠时长、精力、饮食、刷牙、routine workout、日常压力/时间使用等，不仅因为“今天发生了”就复制进 Journal；它们主要用于趋势比较时属于 Well-being。若同一天发生了真正值得以后记住的生活 episode，Journal 可记录 episode 本身，并按需引用相关 Well-being observation，而不是复制整段 telemetry。

系统日志、普通代码修改、实施方案和执行清单留在项目或工具中。项目相关内容只有在体现用户的实际行动、体验、意图或变化时才进入 Journal，不复制 Task 历史或整段聊天。

## 记录什么

用少量文字保留实际知道的时间、发生或表达的内容、必要情境及用户当时的体验。简化措辞，不抹掉区分情境的线索；没有的信息不补猜，不要求每条记录字段齐全。

区分意图、尝试、行动、结果与评价；未记录行动不等于没有行动。发生时间不确定时注明，不把记录时间冒充发生时间。AI 的解释如确需保存，标明推断或待验证理解，不把情绪、梦境或单次行为解释成人格和因果结论。

区分同一事件的再次讲述与新的发生。补充旧事件时关联原记录，确有新的发生或表达时保留新的时间；不把重复叙述计成多次发生，也不将类似事件合并到看不出其先后。提及频率只是部分观察，不等于实际发生频率。

## 维护与分流

默认追加记录。更正用 follow-up 指明修正哪次旧事件，不把后来知道的内容伪装成当时已知；用户明确要求纠正、删除或整理时按其要求处理。归纳或精简不应无声抹去事件时间、区别和不确定性。

写 Journal 时，已确认的可复用个人状态当次按 Personal 规则更新；重复性 observation / behavior 按 Well-being 规则维护；明确的行动、等待或监控按 Task 规则跟进；经过实际权衡且未来值得作为 precedent 的具体选择按 Decision 规则记录。Journal 保留 episode，Well-being 维护纵向 signal，Personal 维护当前长期状态，Decision 维护选择及其当时条件，Task 维护下一步，不复制维护细节和进度。同一对话可以影响多个领域，但各处只保存自己的语义。

当前先保证记录忠实、简洁、可追溯，不为每条片段预先寻找历史关联、生成聚类或读取全部季度 Journal。主动检索与跨事件归纳按需要 progressive retrieval，不是保存的前置步骤。
