# Task Rule

Task 只用于仍然存在未完成动作、外部等待、监控、决策或持续推进需求的事项。

Task 可以保存完成当前事情所需的局部上下文、调研、候选方案、临时发现和工作记录，但它不是永久个人知识库。已经明确、未来会跨任务复用的个人事实或偏好应写入对应 `personal/` 文件；Task 需要时直接引用那里，不再复制维护一份。

## 新建与维护

新 Task 至少要让未来的 AI 能快速知道：这是什么、现在处于什么状态、目标是什么、下一步或触发条件是什么。当前约定的核心字段是：

```markdown
# [ID] — [标题]

- 类型: ACTION | EXTERNAL_WAIT | DECISION | DISCOVERY | MONITORING | EPIC
- 优先级: P0 | P1 | P2 | P3
- 状态: ACTIVE | NEXT | WAITING | SCHEDULED | BLOCKED | BACKLOG | DONE | DROPPED
- 目标结果: ...
- 下一动作 / 触发器: ...
- 依赖: ...
- 最后更新: ...
```

可以根据任务需要增加少量有明确用途的字段或章节，不要求所有 Task 使用完全相同的正文结构。

推进过程中优先更新当前状态和真正影响下一步的信息。不要为了保存聊天过程而不断追加重复内容。

## 结束与归档

Task 结束时先写清最终结果。随后检查是否产生了需要长期保留的内容：可跨任务复用的个人事实、偏好或长期判断写入 `personal/`；重要人生事件或里程碑写入 `JOURNAL.md`。完成这些必要抽取后，再移动到 `archive/<year>/`。

如果没有值得抽取的长期信息，就不要为了流程完整而制造一份。
